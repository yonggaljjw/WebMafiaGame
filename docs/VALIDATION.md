# 검증 결과

이 문서는 제공된 소스에서 직접 실행한 검증과 실행하지 못한 검증을 구분합니다.

## 직접 실행

- Django 시스템 검사: 오류 0개
- 정적 파일 수집: CSS/JS 수집 및 해시/압축 처리 성공
- JavaScript: `node --check game/static/game/app.js` 통과
- `python scripts/test_local.py`: 총 58개 중 **57개 통과, 1개 건너뜀**
- SQLite 기반 Django 테스트 클라이언트로 방 생성, 입장, 준비, 낮/투표 전환, 시민팀 승리, 재경기 흐름 확인
- 비공개 역할·경찰 결과·마피아 채팅·사망자 채팅 노출 방지 확인
- 투표 덮어쓰기, 과반수·동률, 의사 보호, 경찰 조사, 밤 동시 처리, 역할별 권한 확인
- 재접속 유예, 일시정지와 시간 보상, 이탈 후 지속/무효, 방장 승계 확인
- 세션 구분, 외부 참가자의 요청 차단, CSRF, 정원 초과 및 잘못된 입력 차단 확인

## 실행하지 못한 검증

현재 제작 환경에 Docker와 MySQL 서버가 없어 다음은 실행하지 않았습니다.

- Docker 이미지 빌드 및 Compose 실제 기동
- 실제 MySQL/InnoDB 동시 입장 행 잠금 테스트 (1개 skip)
- 실제 다중 기기·브라우저를 통한 수동 플레이
- 브라우저 렌더링/시각 QA, 모바일 절전·백그라운드 타이머 동작
- 포트포워딩·외부 네트워크 접속, 부하 테스트
- 포함된 GitHub Actions 워크플로 실행

SQLite 테스트 통과가 MySQL의 행 잠금이나 Compose 실행 성공을 의미하지 않습니다.
실제 MySQL 테스트와 Compose 상태 확인용 CI를 `.github/workflows/tests.yml`에 포함했습니다.
UI는 HTML/CSS/JavaScript로 구현했으며 실제 브라우저 화면 검증을 완료했다고 주장하지 않습니다.

## 설정 기능 추가 후 검증

기존 43개에 설정 관련 테스트 14개가 추가되어 총 57개가 통과했습니다.
- 모든 시작 인원의 사용자 지정 역할 수와 실제 배정 수 일치
- 사용자 지정 토론·투표·밤 시간이 실제 마감 시각에 반영
- 설정 인원 미달 시 시작 거부와 역할 미배정
- 역할 상한의 6/7/8/9/10인 경계 확인
- 역할 과다·합계 불일치·특수직업 과밀·잘못된 자료형·시간 범위 거절
- 시간 최솟값·최댓값 허용
- 시작 시 저장 설정 재검증
- 재경기에서도 역할 구성과 시간 보존 및 적용
- 두 의사의 서로 다른 대상 보호
- 두 경찰의 독립 조사와 비공개 결과
- bootstrap의 서버 밸런스 카탈로그
- 생성→다른 참가자 입장→시작→낮/투표/밤 API에서 설정 유지·적용
- 준비 완료자가 4명이더라도 8인 설정 방의 시작은 거절
- 위조된 설정의 API 요청 거절 및 방 미생성

실제 브라우저 조작 및 MySQL/Compose 검증의 미실행 범위는 위와 같습니다.
