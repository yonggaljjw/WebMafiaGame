# `game/domain/` — 순수 게임 규칙 계층

> 상위 문서: [game/README.md](../README.md)

이 폴더에는 “Django 서버” 자체보다 **마피아라는 게임이 어떻게 동작하는가**를 담습니다. 가능한 한 HTTP 요청, Django ORM, 템플릿 같은 기술 요소와 분리해 두었습니다.

이렇게 분리하면 게임 규칙을 읽을 때 DB나 네트워크를 함께 생각하지 않아도 되고, 규칙만 따로 테스트하기도 쉬워집니다.

## 파일별 역할

| 파일 | 역할 |
| --- | --- |
| `rules.py` | 인원수, 역할 수, 시간 범위 등 공통 규칙과 검증 |
| `state.py` | 새 게임 상태, 참가자, 메시지, 승패·연결 상태 관리 |
| `phases.py` | 낮 → 투표 → 밤 단계 전환과 시간 만료 처리 |
| `actions.py` | 준비, 시작, 채팅, 투표, 능력 사용, 퇴장, 재경기 |
| `snapshot.py` | 사용자별로 볼 수 있는 정보만 추려서 반환 |
| `__init__.py` | 도메인에서 외부에 공개할 함수를 묶는 진입점 |

## 왜 Domain을 따로 두나?

예를 들어 “투표에서 생존자의 과반수를 얻어야 처형된다”는 규칙은 Django와 관계가 없습니다. DB가 MySQL이든 PostgreSQL이든 게임 규칙은 같아야 합니다.

따라서 다음 두 책임을 분리합니다.

```text
services/: 상태를 안전하게 읽고 저장한다.
domain/:   그 상태를 어떤 규칙으로 바꿀지 결정한다.
```

## `state.py`

게임 상태의 자료구조를 만들고, 참가자 목록·로그·연결 상태·승리 상태 같은 공통 데이터 처리를 담당합니다.

채팅 메시지도 이 상태에 기록됩니다. 현재 버전에서는 일반 메시지에 `sender_id`를 기록하여 브라우저가 닉네임 문자열이 아니라 **실제 참가자 ID를 기준으로 내 메시지를 판별**할 수 있습니다.

## `actions.py`

사용자가 직접 일으키는 행동이 모입니다.

예:

- 준비 상태 변경
- 게임 시작
- 채팅 전송
- 투표
- 마피아 공격 대상 선택
- 의사 보호
- 경찰 조사
- 방 나가기
- 재경기

여기서 중요한 점은 브라우저가 “내가 마피아니까 이 사람을 죽였다” 같은 최종 결과를 보내지 않는다는 것입니다. 브라우저는 **의도만 요청**하고, 실제로 가능한 행동인지와 결과는 서버 Domain이 판정합니다.

## `phases.py`

시간에 따라 자동으로 일어나는 변화가 들어갑니다.

예:

```text
낮 토론 종료
  ↓
투표 단계
  ↓
투표 종료 및 처형 판정
  ↓
밤 단계
  ↓
공격/보호/조사 동시 처리
  ↓
승패 확인 후 다음 낮
```

브라우저에서 타이머 숫자를 표시하더라도 실제 단계 전환 기준은 서버 시간입니다.

## `snapshot.py` — 보안상 특히 중요한 파일

같은 Room 상태를 보고 있어도 사용자마다 받아야 하는 정보가 다릅니다.

예를 들어:

- 시민은 다른 사람의 역할을 알 수 없음
- 마피아는 같은 마피아를 확인할 수 있음
- 경찰 조사 결과는 해당 경찰에게만 보여야 함
- 사망자 채팅은 생존자에게 노출되면 안 됨

그래서 원본 state를 그대로 반환하지 않고 `snapshot()`을 거쳐 사용자 전용 응답을 만듭니다.

**프런트에서 `display:none`으로 숨기는 것은 보안이 아닙니다.** 개발자 도구에서 응답 JSON을 볼 수 있기 때문입니다.

## 새 규칙 추가 예시

“경호원” 역할을 추가한다고 가정하면 대략 다음을 봅니다.

1. `rules.py`: 역할 수 검증
2. `state.py`: 역할 배정이나 상태 필드
3. `actions.py`: 경호 대상 선택
4. `phases.py`: 밤 결과 처리
5. `snapshot.py`: 경호원에게 필요한 정보 공개
6. `tests.py`: 공개정보/행동/승패 회귀 테스트

## 학습 포인트

- Domain Logic과 Framework Logic의 분리
- 상태 머신(State Machine)
- 서버 권한 검증
- 사용자별 정보 필터링
- 순수 함수에 가까운 구조가 테스트하기 쉬운 이유
